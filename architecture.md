# architecture.md

## Назначение

Этот документ определяет архитектурные правила для backend TheChat.

Цель — сохранять backend:
- модульным
- явным
- тестируемым
- удобным для развития
- безопасным для сценариев чата в реальном времени

Этот проект должен быть построен как **модульный монолит**, а не как ad hoc набор роутов и утилит.

---

## Архитектурный стиль

### Основной стиль

Используйте **модульный монолит** с явными доменными границами.

Почему:
- проще микросервисов на этом этапе
- проще локальная разработка и отладка
- проще поддерживать согласованность для auth, messages, presence и realtime flows
- при необходимости все еще позволяет в будущем выделять модули

### Ключевой принцип

Организуйте код по **домену/модулю**, а не только по широким техническим категориям.

Предпочитайте:
- `modules/messages`
- `modules/chats`
- `modules/presence`

Не полагайтесь на структуру только верхнего уровня вроде:
- `controllers/`
- `services/`
- `repositories/`

как на главный принцип организации всего приложения.
