# AGENTS.md - src/db/migrations

## Реальная ответственность директории

Пошаговая история SQL-изменений схемы PostgreSQL.

## Что менять здесь уместно

- Добавлять новые миграции при изменении схемы.
- Добавлять idempotent repair-миграции при необходимости.

## Что менять здесь неуместно

- Переписывать старые примененные миграции без аварийной причины.
- Класть TypeScript или бизнес-логику.

## Границы зависимостей

- Только SQL DDL/DML для миграций.
- Никаких зависимостей на `modules`, `plugins`, `shared`.
- Для long-lived таблиц учитывать backfill, nullable rollout, constraint validation и совместимость с тестовым мигратором.

## Куда класть новый код

- Любое изменение структуры БД - отдельный `000X_*.sql` в этом каталоге.

## Связанные файлы

- `src/db/schema/*`
- `src/db/migrations/meta/_journal.json`
- scripts: `npm run db:migrate`, `npm run db:generate`

## Локальный чеклист перед завершением

1. Номер миграции следующий по порядку.
2. Миграция применима поверх текущего состояния.
3. Имена индексов/constraint не конфликтуют.
4. `src/db/schema/*` и `meta/_journal.json` синхронизированы с новой миграцией.
5. `npm run db:migrate` на реальной БД, если она доступна; иначе migration-backed тесты и явное ограничение в финальном ответе.

## Типичные ошибки будущего агента

- Удалить защитный `IF NOT EXISTS` в repair-миграции без причины.
- Внести schema-изменение без соответствующей миграции.
- Добавить constraint без учета существующих данных.
