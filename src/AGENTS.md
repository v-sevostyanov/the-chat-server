# AGENTS.md - src

## Реальная ответственность директории

`src` содержит весь production-код backend-сервиса.
Структура разделена на слои: `app`, `plugins`, `modules`, `db`, `shared`.

## Что здесь уместно менять

- Архитектурные связи между слоями.
- Глобальные правила структуры `src`.
- Документацию по навигации по коду.

## Что здесь неуместно

- Бизнес-логику в корне `src`.
- Случайные "общие утилиты" вне `shared/*`.
- Перенос кода между слоями без архитектурной причины.

## Границы и зависимости

- `modules/*` могут зависеть от `shared/*`, `db/schema`, Fastify decorators.
- Raw DB/query logic должна оставаться в repository/data-access слое модуля.
- `plugins/*` дают инфраструктуру, но не доменные сценарии.
- `shared/*` не должен зависеть от `modules/*`.
- `app/*` только собирает приложение.
- Cross-module взаимодействие делать через явные adapter/contract точки, а не через прямой импорт чужих service/repository.

## Куда класть новый код

- Новый доменный сценарий: `modules/<domain>`.
- Новый инфраструктурный capability: `plugins/<name>`.
- Новая таблица/миграция: `db/schema` + `db/migrations`.
- Общий cross-module примитив: `shared/*`.

## Связанные файлы

- `src/app/app.ts`
- `src/modules/index.ts`
- `src/plugins/*/*.plugin.ts`
- `src/db/schema/*`

## Локальный чеклист перед завершением

1. Изменение осталось в правильном слое.
2. Не добавлена лишняя связность между модулями.
3. При изменении типов/контрактов: `npm run typecheck`.
4. При runtime-изменениях: `npm run lint` и `npm run test`.

## Типичные ошибки будущего агента

- Положить бизнес-правило в plugin.
- Добавить shared-код, который знает детали одного домена.
- Достучаться из handler/service напрямую до чужой таблицы вместо явного доменного контракта.
