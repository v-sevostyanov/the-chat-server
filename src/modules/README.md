# src/modules

## Назначение

`modules` — доменное ядро приложения.
Каждый модуль инкапсулирует свой bounded context: маршруты, обработчики, бизнес-правила, доступ к данным и контракты DTO.

## Подключённые модули

- `health` — liveness/readiness.
- `auth` — регистрация, логин, refresh rotation, logout, `me`.
- `users` — профиль и поиск пользователей.
- `chats` — создание/чтение чатов.
- `messages` — отправка и чтение истории сообщений.
- `presence` — онлайн-статус и last-seen.

Регистрация модулей выполняется в `modules/index.ts`.

## Единый шаблон слоя в модуле

Типичный pipeline:

1. `*.routes.ts` — HTTP-контракт и схема валидации.
2. `*.handlers.ts` — минимальная транспортная логика.
3. `*.service.ts` — доменные правила.
4. `*.repository.ts` — запросы в БД/Redis.
5. `*.mapper.ts` / `*.types.ts` / `*.schemas.ts` — DTO и сериализация.

## Границы и зависимости

- Модули могут использовать `shared/*`, `db/*` и инфраструктурные decorators Fastify.
- Прямые зависимости между доменными модулями должны быть минимальны и явны.
- Для realtime-интеграции используются адаптеры через `fastify.realtime`:
  - `presence` биндует presence-adapter.
  - `chats` биндует chats-adapter.

## Правила расширения

- Новый домен добавляется отдельной директорией в `modules`, а не в существующий модуль.
- Не смешивать transport и data-access: route/handler не должны выполнять SQL-запросы.
- При изменении API обязательно обновлять TypeBox-схемы и примеры.
- Любой non-trivial модульный change должен сопровождаться проверкой auth/error-path и edge-case сценариев.
