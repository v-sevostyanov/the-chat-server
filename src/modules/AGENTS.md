# AGENTS.md - src/modules

## Реальная ответственность директории

`src/modules` - доменный слой backend.

Текущие модули:

- `health`
- `auth`
- `users`
- `chats`
- `messages`
- `presence`

## Что менять здесь уместно

- Подключение/порядок регистрации модулей в `index.ts`.
- Добавление нового модуля как отдельной директории.

## Что менять здесь неуместно

- Инфраструктурную логику plugins.
- SQL/redis bootstrap.
- Объединение нескольких доменов в один "универсальный" модуль.

## Границы зависимостей

- Каждый модуль держит слой `routes -> handlers -> service -> repository`.
- Прямые импорты между модулями минимальны; предпочитать явные интерфейсы/адаптеры.
- Если модулю нужен cross-domain факт, сначала ищи существующий adapter/contract, а не импортируй чужой service/repository.

## Куда класть новый код

- Новый use-case - в конкретный модуль.
- Новый домен - новая папка модуля + регистрация в `modules/index.ts`.

## Связанные файлы

- `src/modules/index.ts`
- `src/app/app.ts`
- `src/plugins/websocket/realtime.types.ts`

## Локальный чеклист перед завершением

1. Изменение не размывает границы модулей.
2. Изменение API отражено в `*.schemas.ts`.
3. Для runtime-изменений: `npm run typecheck`, `npm run lint`, `npm run test`.

## Типичные ошибки будущего агента

- Писать SQL в handlers.
- Переносить бизнес-правила в mappers.
- Создавать скрытую связность между модулями через удобный прямой импорт.
